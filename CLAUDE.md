# Дневник атмосферы — Genesis ArtTech 2026 («Make the Invisible Visible»)

## Цель и как нас оценивают
Личный дневник: пользователь вводит текст о дне, фото и песню, система превращает это в воспоминание (вертикальное видео + постер), которое передаёт АТМОСФЕРУ дня, и сохраняет в папку дня с придуманным названием. Архив дней листается как один дневник.

Критерии (100): атмосфера дня 30 · визуальная система 25 · техника 20 · связь ввода и результата + UX 15 · демо и объяснение 10.
Жюри штрафует «грустно — значит синий» и «один эффектный шаблон без системы». Выигрывает глубина связи между днём и формой и объяснимость.
Дедлайн: 22.11.2026 23:59 (Астана, UTC+5).

## Принципы (не нарушать)
1. Атмосфера важнее количества фич. Каждая фича должна быть видна в 3-минутном демо-видео.
2. Каждое визуальное решение порождается ПРАВИЛОМ и записывается в `decisions[]` (вход → правило → результат). Никакого рандома без seed. Одинаковый ввод → одинаковый результат.
3. Работает без ключей и без сети (fallback на правила). LLM — улучшение, а не зависимость.
4. Своя визуальная система — процедурный WebGL-пайплайн, а не генерация картинок нейросетью. Это наш вклад и наша объяснимость.
5. Не добавлять ничего вне этой спеки без запроса.

## Стек
- Vite + TypeScript, без фреймворка (vanilla + модули). WebGL2 (сырые шейдеры, маленький хелпер).
- `essentia.js` (WASM) в Web Worker — аудиоанализ. `idb` — IndexedDB. `jszip` — fallback для папки.
- Шрифты с кириллицей: Cormorant Garamond (название), JetBrains Mono (дата/служебное), Marck Script или Caveat (рукописная подпись), Inter (интерфейс).
- Деплой: Vercel или GitHub Pages. README с одной командой запуска.

## Анализ
### Текст
- LLM через OpenAI-совместимый endpoint (провайдер и ключ вводятся в Настройках, хранятся в localStorage, НИКОГДА не в репозитории). Строгий JSON по схеме Mood + `title` + `caption` + `sensory`. Мотивы выбираются ТОЛЬКО из библиотеки (см. ниже). Валидация, 1 повтор, затем fallback.
- Fallback `text-rules.ts`: словарь русских основ (с учётом окончаний) → valence/arousal/warmth/social/время/сезон/мотивы. Сохранять найденные слова-триггеры как evidence.

### Фото
k-means на 5 цветов в пространстве LAB (по уменьшенной до 96px копии), яркость, насыщенность, контраст, цветовая температура, плотность краёв (спокойный/«шумный» кадр). Выбрать hero-фото (резкость + контраст). Число фото → ритм монтажа.

### Музыка (приоритет источников)
1. Свой файл пользователя → полный анализ.
2. Официальный 30-секундный фрагмент через iTunes Search API (поиск по «исполнитель — название»). ПРОВЕРИТЬ CORS для анализа через Web Audio; если анализ недоступен — фрагмент только играет, признаки берутся из п.3.
3. Только ссылка/название → признаки оценивает LLM по исполнителю/названию/году (помечать `featuresFrom: 'description'` и показывать это честно).
essentia.js в воркере: RhythmExtractor2013 (BPM + позиции битов), KeyExtractor (тональность + мажор/минор), громкость/энергия, спектральный центроид, danceability.

### Слияние
Непрерывные веса (текст 0.45, музыка 0.35, фото 0.2), скорректированные на confidence каждого источника. Конфликты (весёлый текст + минорная песня) — не усреднять в серость, а превращать в приём: «светлая грусть» = тёплая палитра + замедление + плёнка. Записывать в decisions.

## Визуальная система
### Константы (делают ленту одним дневником)
- Формат: видео 9:16 (рендер 720×1280, постер 1080×1920) + карточка ленты 4:5 (кроп постера).
- Сетка 12 колонок, поля 6%. Дата всегда слева сверху (JetBrains Mono, «21.11.2026 · сб · вечер»). Название всегда снизу (Cormorant Garamond). Рукописная подпись — одна строка над названием. Номер страницы дневника справа сверху.
- Общая бумажная фактура-подложка на всех днях (меняется только интенсивность и тон).

### Переменные
Палитра и цветокоррекция, сила «живописи», зерно/плёнка, геометрия, мотивы-частицы, скорость камеры, ритм склеек, количество воздуха (масштаб фото в кадре), насыщенность и межбуквенный интервал типографики.

### Художественные режимы (смешиваются весами, а не if/else)
| Режим | Когда | Приём | Почему передаёт ощущение |
|---|---|---|---|
| Импрессионизм (Моне) | спокойно, тепло, valence > 0 | анизотропный фильтр Кувахары + мягкие растворения, дрожание света | размытая граница = память о свете, а не о деталях |
| Геометрия (Кандинский) | высокий arousal, напряжение | SDF-фигуры, линии и пятна в такт битам, жёсткая сетка, резкие склейки | ритм и форма вместо предмета = внутреннее напряжение |
| Плёнка / ностальгия | минор, старая песня, вечер, воспоминания | зерно, halation, виньетка, light leak, дрожание кадра, тёплые тени | язык семейного архива = «это было давно и важно» |
| Японский минимализм | тихо, одиноко, низкий social | много пустоты, одно маленькое фото, тонкая линия, очень медленно | пустота = тишина и дистанция |
| Коллаж | много людей и фото, праздник | рваные края, наложения, кадры «приклеиваются» на сильные доли | теснота и наложения = шум и тепло компании |
Каждый день: основной режим + второстепенный с долями из параметров Mood.

### Библиотека мотивов (текст → конкретные визуальные элементы, это наш главный аргумент против «грустно = синий»)
листья, дождь (полосы + капли на «стекле»), снег, туман, боке городских огней, свеча, звёзды, солнечные блики, пар от кружки, волны (дисплейсмент), ветер (линии), конфетти, пыль в луче, тени листвы, неон. Для каждого: слова-триггеры, вид, как музыка его модулирует (энергия → плотность, BPM → скорость, яркость звука → резкость).

### Музыка → форма
- Склейки и пульсации на РЕАЛЬНЫХ битах (из beats[]); при низкой энергии — каждые 8 долей, при высокой — каждые 2.
- Энергия → амплитуда движения и плотность частиц. Мажор/минор → светлота и насыщенность. Спектральная яркость → резкость краёв. Год песни → сила плёнки.
- Длительность видео = целое число музыкальных фраз (15–30 с), фейд звука в начале и в конце.

### Шейдерный пайплайн (WebGL2, все параметры из DayStyle)
1) раскладка фото + Ken Burns + переходы → 2) цветокоррекция (lift/gamma/gain + split-toning из палитры и Mood) → 3) Кувахара (сила) → 4) геометрический слой (SDF) → 5) частицы мотивов → 6) плёнка (зерно, halation, виньетка, light leak, дрожание кадра) → 7) бумага + типографика (2D canvas как текстура).
Цель: 30 fps при 720p на встроенной видеокарте. Если не тянет — снизить радиус Кувахары, а не качество типографики.

### Название дня
3–7 слов, один тон: конкретная деталь + время/место, тепло и просто, без пафоса и штампов («незабываемый», «волшебный»), без эмодзи. Примеры: «Осенний парк и какао», «Ночь в офисе перед сдачей», «Дождливое утро без будильника». Проверка длины, без повторов в архиве.

### Голос (бонус)
Web Speech API, русский голос; rate и pitch выбираются правилами из Mood (спокойный вечер: 0.85/0.9; насыщенный день: 1.15/1.05). Правило записывается в decisions.

## Выход
- **Папка дня**: File System Access API — пользователь один раз выбирает корневую папку «Дневник» (handle хранится в IndexedDB), каждый день пишется в `2026-11-21 — Осенний парк и какао/`: `запись.txt`, `photos/`, `memory.webm`, `poster.png`, `voice.webm` (если есть), `песня.txt` (название, исполнитель, ссылка), `day.json` (Mood, DayStyle, decisions). Аудиофайл кладётся только если его загрузил сам пользователь. Fallback для других браузеров — ZIP.
- **Видео**: canvas.captureStream(30) + аудио через MediaStreamDestination → MediaRecorder (VP9/Opus). Если при записи падает fps — переключиться на покадровый офлайн-рендер через WebCodecs + Mediabunny (MP4).

## Архив
- Лента: сетка карточек 4:5, дата + название. Должна выглядеть как дневник одного человека.
- Режим «Проверка лентой»: 5–7 дней в ряд на одном экране (прямо отвечает критерию жюри).
- Страница дня: видео с музыкой, текст, фото, голос, блок «Почему день выглядит так» (3–5 строк из decisions).
- «Рентген дня»: переключатель, который поверх воспоминания показывает цепочки «слово/цвет/бит → правило → эффект». Главный инструмент для демо.
- Поиск по названию и тексту, фильтр по месяцу, удаление.

## Демо-контент
- Дни команды с НАСТОЯЩИМИ фото (свои или с согласия людей). Музыка — свободная лицензия (Free Music Archive, Pixabay Music, Incompetech CC-BY) или официальные фрагменты. Указать источники в TOOLS.md.
- Плашка в интерфейсе: «Настроение определяется алгоритмом по словам, фото и музыке и не является психологической оценкой».

## Как работать (для Claude Code)
- Фазами. После каждой фазы: `npm run build` без ошибок → запустить dev-сервер → сделать скриншоты (Playwright) минимум 3 дней с разным настроением → самому оценить, отличаются ли дни и похожи ли на один дневник → исправить → `git commit`.
- Не ломать fallback без ключа. Не хардкодить ключи.
- Обновлять docs/VISUAL_SYSTEM.md и docs/TECHNIQUES.md по мере появления правил.
- Важна производительность: рендер не должен блокировать UI, аудиоанализ — в воркере.

## Фазы
1. Каркас: ввод → анализ фото + текст по правилам → DayStyle + decisions → WebGL-пайплайн (цветокоррекция + Кувахара + плёнка + типографика) → постер → архив в IndexedDB.
2. Музыка: essentia.js в воркере, iTunes-фрагменты, бит-синхронный таймлайн, проигрывание воспоминания.
3. Все 5 режимов + смешивание + библиотека мотивов.
4. LLM-анализ текста, названия и подписи (с fallback), разрешение конфликтов.
5. Видео, папка дня (FS Access + ZIP), голос.
6. Лента, «Проверка лентой», «Рентген», поиск, полировка UI, документация, деплой.
