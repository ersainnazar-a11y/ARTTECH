# Техники

## Анализ
- **Текст без сети** (`analysis/text-rules.ts`): словарь русских основ (`груст*`) и точных форм; учитывает отрицание («не», «без») и усилители («очень»). Суммы по осям сжимаются через `tanh`. Каждое найденное слово сохраняется как evidence.
- **Фото** (`analysis/photo.ts`): уменьшенная копия 96px → LAB, k-means++ (k = 5) с seed от пикселей. Считаются яркость (L), насыщенность (хрома), контраст (σL), температура (b*, a*), плотность краёв (Собель) и резкость (дисперсия лапласиана). Hero-фото выбирается по 0.6·резкость + 0.4·контраст.
- **Слияние** (`analysis/fuse.ts`): веса текст 0.45 / музыка 0.35 / фото 0.2, каждый умножен на confidence источника. В фазе 1 музыка не анализируется (confidence 0).

## WebGL2-пайплайн (`render/gl/`)
1. `grade.frag` — раскладка фото в кадре (поворот, кадрирование cover) + экспозиция в линейном свете → lift/gamma/gain → контраст → насыщенность → split-toning (soft-light) → тёплые тени.
2. `tensor.frag` + `blur.frag` ×2 — структурный тензор (Собель), сглаженный гауссом.
3. `kuwahara.frag` — анизотропный фильтр Кувахары (Kyprianidis 2009/2011, полиномиальные веса, 8 секторов). Эллипс вытянут вдоль структуры, поэтому мазок идёт по форме предмета. Проход режется на полосы (scissor), чтобы не упереться в сторожевой таймер GPU.
4. `blur.frag` с bright-pass на ¼ разрешения — halation.
5. `composite.frag` — процедурная бумага (fbm-пятна + волокна), маска отпечатка (SDF прямоугольника + шум рваного края, растворение, белая рамка, тень), halation, light leak (screen), виньетка, зерно, впитывание чернил типографики.

Типографика рисуется на 2D canvas (`render/overlay2d.ts`) и передаётся текстурой.

Постер 1080×1920 рендерится примерно за 0.5–1.8 с на встроенной видеокарте.

## Детерминированность
`seed = FNV-1a(дата | текст | хэши пикселей фото | песня)`. Все «случайные» величины (угол засветки, наклон подписи, знак поворота, зерно) берутся из `mulberry32(seed)`. `Math.random` нигде не используется.

## Самопроверка
`npm run shoot` поднимает Vite, создаёт 5 дней с разным настроением через Playwright (Edge/Chrome из системы) и сохраняет постеры и скриншоты в `shots/`.

## Музыка (фаза 2)
- **Источники по приоритету** (`analysis/song-meta.ts`, `day.ts → resolveSong`):
  1. свой файл — анализ целиком (длинный трек: 60 с начиная с 25% длительности);
  2. официальный 30-с фрагмент через iTunes Search API. CORS проверен: `Access-Control-Allow-Origin: *` и у поиска, и у `audio-ssl.itunes.apple.com`, поэтому фрагмент анализируется полностью;
  3. только метаданные — признаки по таблице жанров, `featuresFrom: 'description'`, уверенность 0.35. На странице дня написано «оценка по описанию, не по звуку».
- **Декодирование** в основном потоке (`decodeAudioData` в воркере недоступен) → `OfflineAudioContext` моно 44.1 кГц → передача `Float32Array` в воркер (transferable).
- **Воркер** (`analysis/audio.worker.ts`, essentia.js WASM): `RhythmExtractor2013` (degara) → BPM и позиции битов; `KeyExtractor` (bgate) → тональность и лад; `Danceability`; `Windowing → Spectrum → Centroid` по кадрам → спектральная яркость; RMS → громкость. Энергия = 0.55·громкость + 0.25·темп + 0.2·danceability. Уверенность ритма — регулярность межбитовых интервалов.
- **Проверка точности** на синтетике с известными параметрами (`scripts/make-test-audio.mjs`): 128 BPM до мажор → 128.19 BPM C major; 70 BPM ля минор → 69.97 BPM A minor. Анализ занимает около 2 с.

## Воспоминание: бит-синхронный монтаж (`render/timeline.ts`, `render/player.ts`)
- Пайплайн разделён на подготовку и кадр. Цветокоррекция и Кувахара считаются **один раз на фото** (`Pipeline.paint`). Каждый кадр — это только раскладка, Ken Burns, переход, halation, плёнка и бумага. Итог: 60 fps при 720×1280.
- `buildTimeline` — чистая функция от стиля, битов, числа фото и seed. Склейки стоят на реальных битах `beats[i·beatsPerCut]`. Растворения центрированы на доле, жёсткие склейки попадают точно в долю.
- Пульсация — затухающий импульс `exp(−dt/0.11)` на каждую долю, сильная доля (каждая 4-я) ×1.6. Это даёт вспышку экспозиции и толчок масштаба.
- Дрожание плёнки — около 12 раз в секунду, амплитуда от веса плёнки и коллажа. Зерно меняется 24 раза в секунду.
- Часы воспроизведения — `audio.currentTime`, поэтому картинка не уплывает от звука. Звук плавно появляется и уходит за 1.2 с.

## Слои кадра (фаза 3)
Кадр собирается так: `layout` (+ дисплейсмент волн) → halation → `base` (бумага, отпечаток, плёнка, мерцание, вспышка, линия) → карточки коллажа → геометрия → мотивы → `final` (чернила + общее зерно). Средние три слоя рисуются в текстуру `base` с премультиплицированным смешиванием `ONE, ONE_MINUS_SRC_ALPHA`. Свет (дождь, боке, блики, неон) пишется с альфой 0, то есть аддитивно. Предметы и тени (листья, конфетти, капли, тени листвы) пишутся с альфой.

Общие функции (шум, fbm, SDF, бумага, маска отпечатка с рваным краем) лежат в `shaders/common.glsl` и подставляются перед телом шейдера.

Мотивы процедурные, без текстур: частицы раскладываются по ячейкам сетки с хэшем от id ячейки, по 2–3 слоя глубины. Плотность — доля занятых ячеек. Постер — это стоп-кадр в момент `t = 3 + (seed mod 1000)/250`, так что он детерминирован.

Производительность: 60 fps при 720×1280 со всеми слоями.

## LLM-анализ текста (фаза 4, `analysis/text-llm.ts`)
- Используется любой OpenAI-совместимый endpoint: OpenAI, OpenRouter, Ollama. Endpoint, модель и ключ вводятся в «Настройках» и хранятся **только** в `localStorage` браузера. В репозитории ключей нет.
- Запрос: `temperature: 0`, `seed: 7`, `response_format: json_object`, системный промпт со строгой схемой Mood + `motifs` + `evidence` + `sensory` + `title` + `caption` + `confidence`.
- **Валидатор** проверяет:
  - числа в диапазонах и значения из перечислений;
  - мотивы — только из библиотеки и только со словами, которые реально есть в тексте;
  - слова-доказательства тоже должны быть в тексте;
  - название: 3–7 слов, без штампов («незабываемый», «волшебный», …) и эмодзи, без повтора в архиве;
  - подпись: до 60 символов.
- **Один повтор:** модели возвращаются её ошибки. Если и вторая попытка не прошла или сеть недоступна — fallback на словарь правил. На странице дня это честно записано.
- **Детерминированность:** валидный ответ кэшируется по хэшу (модель + endpoint + текст). Повторный ввод даёт тот же результат даже без сети.
- **Перекрёстная проверка:** если словарь и модель расходятся по знаку валентности (например, при иронии), берём модель и записываем расхождение в решения.
- **Песня без звука:** модель оценивает BPM, энергию, яркость, лад и год по исполнителю и названию (`featuresFrom: 'description'`, `describedBy: 'llm'`, уверенность ≤ 0.5). Если модели нет — таблица жанров.

## Конфликты (`analysis/fuse.ts`)
| Конфликт | Условие | Приём |
|---|---|---|
| «светлая грусть» | весёлый текст + минорная песня, или тёмное фото днём | плёнка +0.3, тёплые тени, склейки реже в 2 раза, камера ×0.75, больше воздуха |
| «держаться бодро» | тяжёлый текст (valence < −0.25) + мажорная песня с энергией > 0.5 | минимализм +0.35: пустой кадр от слов, а склейки и пульс — на бодрых долях |
| «тихое напряжение» | суетный текст + спокойный кадр | геометрия +0.25 |

## Проверка без ключа
`node scripts/shoot-llm.mjs` поднимает mock OpenAI-сервера (`scripts/mock-llm.mjs`). Сценарии:
- первый ответ нарочно невалиден → проверяется повтор;
- ответ «не JSON» дважды → проверяется fallback;
- ироничный текст → проверяется расхождение со словарём;
- песня только по названию → проверяется оценка по описанию;
- грустный текст + бодрая песня → проверяется конфликт «держаться бодро».

## Выход (фаза 5)
### Видео (`output/video.ts`)
- **Основной путь:** `canvas.captureStream(30)` + фрагмент песни через `AudioContext → MediaStreamDestination` → `MediaRecorder` (VP9/Opus, 5 Мбит/с, `.webm`). Часы записи — `AudioContext.currentTime`, поэтому кадр всегда соответствует моменту звука.
- **Фейды:** фрагмент [start, start + duration] заранее рендерится в `OfflineAudioContext` с плавным появлением и затуханием за 1.2 с.
- **Если fps < 24** (проверка после 1.5 с записи): запись прерывается, и включается **покадровый офлайн-рендер** WebCodecs + Mediabunny. Кадр i рисуется в точный момент i/30, затем `CanvasSource` (H.264) + `AudioBufferSource` (AAC) → `.mp4` с fastStart. Если H.264 недоступен — VP9/Opus в WebM.
- **Проверено** (`scripts/shoot-out.mjs`, разбор файлов Mediabunny в Node):
  - реальное время: WebM VP9 720×1280 + Opus 48 кГц, 29.97 с, 60 fps;
  - офлайн: MP4 AVC 720×1280 + AAC 48 кГц, 29.97 с, рендер около 61 кадра/с (быстрее реального времени).

### Папка дня (`output/folder.ts`)
- **File System Access:** корневая папка «Дневник» выбирается один раз, её handle хранится в IndexedDB (store `handles`). Разрешение проверяется через `queryPermission`, а запрашивается только по жесту пользователя.
- **Структура:** `YYYY-MM-DD — Название/` → `запись.txt`, `photos/01-главное.jpg…`, `poster.png`, `memory.webm|mp4`, `песня.txt`, `day.json` (Mood, DayStyle, decisions). Аудио кладётся **только** если его загрузил сам пользователь — фрагменты iTunes не сохраняются.
- **Автосохранение:** если разрешение уже выдано, папка дня пишется сразу при создании дня. Видео дописывается после записи.
- **Fallback:** ZIP (jszip) с той же структурой. Проверено через OPFS (`navigator.storage.getDirectory()` — тот же API без диалога) и разбором ZIP в Node.

### Голос (`output/tts.ts`)
- Web Speech API, русский голос (предпочтительно «natural/online»).
- rate = lerp(0.85, 1.15, драйв), pitch = lerp(0.9, 1.05, …), вечером чуть медленнее. Правило записывается в decisions.
- Синтез браузера нельзя записать в файл без захвата вкладки, поэтому голос звучит на странице дня, а `voice.webm` не создаётся (в спеке — «если есть»).
